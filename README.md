## Running it locally

1. Open this folder in VS Code.
2. Install the "Live Server" extension if you don't have it.
3. Right-click `index.html` → "Open with Live Server".
4. Must be served over `http://localhost:...` — opening `index.html`
   directly as a `file://` URL fails, because ES modules and the GLB
   fetch are blocked by the browser's CORS rules for local files.
5. If you've just received an updated build and it looks unchanged,
   do a hard refresh (Ctrl+Shift+R) or open in a private window —
   browsers cache ES module scripts aggressively.

## Deploying to GitHub Pages

You'll need a free GitHub account and Git installed. Two ways to do
this — pick one.

### Option A — GitHub Actions (the included workflow, recommended)

1. Create a new repository on GitHub (public, since Pages needs a
   public repo unless you're on a paid plan).
2. From this folder, run:
   ```
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<repo-name>.git
   git push -u origin main
   ```
3. On GitHub: go to your repo → **Settings → Pages** → under "Build
   and deployment", set **Source** to **GitHub Actions**.
4. Push to `main` (or re-run the workflow from the **Actions** tab)
   and it deploys automatically. The workflow file is already at
   `.github/workflows/deploy.yml` — nothing else to configure.
5. Your site will be live at `https://<your-username>.github.io/<repo-name>/`.

### Option B — Plain branch deploy (no Actions)

1. Same `git init`/push steps as above.
2. Settings → Pages → Source: **Deploy from a branch** → Branch:
   `main`, folder: `/ (root)` → Save.
3. Same resulting URL, just without the Actions workflow running.

Either way works — every path in this project is relative (no leading
`/`), so it renders correctly whether it's served from the domain root
or from a `/<repo-name>/` subpath.

### Before you push

- `map.glb` is ~1.15MB — well under GitHub's limits, no Git LFS needed.
- Double check `.gitignore` doesn't exist and accidentally exclude
  `assets/models/map.glb` (it shouldn't, since there isn't one here,
  but worth a glance if you add one later).

## Portal (index.html)

- **Slide-to-enter** is the primary control — dragging previews the
  camera push forward in real time; releasing past ~82% hands off
  into the full entry sequence, short of that springs back. A compact
  text button and the Enter key both work as accessible alternatives.
- **Procedural gate** — no `gate.glb` was provided, so the gate is
  built from Three.js primitives in `scene.js`. Swap in a real model
  later inside `_buildGate()` if you get one.
- **1500-particle field, floor grid, camera breathing, mouse-tilt on
  the entrance card** — all in `scene.js` / `portal.js`.
- **Entry sequence** — panel dissolve → blackout → gate ignition +
  welcome text → camera fly-through → redirect to `map.html`.

## Map (map.html)

- **Building data** (`data.js`) was generated by directly inspecting
  `map.glb`'s node/mesh/material hierarchy — not guessed. Keyed by
  glTF node name, 28 buildings identified via material name pairs.
  Categories are a best-effort classification; descriptions are short,
  honest placeholders — edit `data.js` directly to improve them.
- **Ghost-state coloring** — every building loads in a single muted
  gray regardless of its source material color, then switches to its
  faculty color (from `categoryColors` in `data.js`) on hover/select,
  with a glow. This overrides whatever's baked into the GLB, so there
  was no need to touch materials in Blender.
- **Auto-fit camera** — computes the model's real bounding box,
  recenters it, and derives camera position/zoom limits from the
  actual size, robust to the one known outlier mesh (see below).
- **Selection pulse** — clicking a building spawns a one-shot
  expanding ring at its base in the actual 3D scene, in its faculty
  color.
- **Search, camera focus + reset, hover tooltip** — all in `map.js`.
- **Staggered UI entrance** — header/HUD/legend/controls fade in with
  a slight delay once the model finishes loading.

## Known issue worth fixing at the source eventually

The "Laboratories, Faculty of Engineering" mesh (node
`building_curve_.058`) has one vertex roughly 145,000 units away from
the rest of its own geometry — almost certainly a stray vertex from
modeling, not intentional. `map.js` sanitizes this at runtime (snaps
outlier vertices back into the mesh's own cluster) so it renders and
auto-fits correctly, but it's worth fixing in Blender directly at some
point: open that mesh in edit mode, select all, and look for one
vertex sitting far outside the rest.
